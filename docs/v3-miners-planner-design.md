# V3 public miners planner

Audience: mining operators evaluating the relationship between fleet production and a binary difficulty contract. Primary action: review an explicitly selected YES or NO market in the app. Source reference: app `/app/miners`, a user-requested functional reference; the former public text-only page was rejected.

The public composition keeps the reference's production → contract → estimate sequence, with a visible objective switch, a fleet worksheet, selectable contract rows and a distinct estimate/review area. Dark brand tokens, Manrope, restrained blue states and tabular figures match the V3 resource library. On mobile the sequence becomes a single column; every chart value is also text. Existing `#planning-example` entry links still land on the planner.

Only cbBTC contracts size BTC production. Other denominations require a conversion source and remain available through the desk explorer. Production horizon and contract observation block stay separate. Prices are indicative source summaries, never size-specific executable quotes. YES protection rounds payout to 0.01 before pricing, matching app math; NO is buying exposure, not selling an option. Decimal inputs remain rational through calculations. No amount is transferred, and no wallet, terms, signature or order is triggered.

The same-origin read-only adapter reads fixed public application endpoints with timeouts and no cache. Incomplete snapshots fail; missing average fees require a visible manual assumption. Restricted-location responses remain unavailable, with no bypass or synthetic fallback. Snapshot age, failed refresh, no markets, invalid calculation and removed selection all have explicit states. Selection uses immutable ID plus full tuple and never clamps to another market. A fresh preflight revalidates identity before the dedicated app review route, with changed-selection and unmount guards.

Deployment dependency: deploy the frontend `/app/market-review/...` guard and its `/api/market-review-support` version1 handshake before enabling the new review destination. The website probes support before navigation; unsupported or unavailable apps show a message and the existing market-list link. Existing production detail routing remains unchanged.

Verification: `scripts/check-public-markets.mjs` covers normalization, invalid/duplicate contracts, exact values, identity, URL fields, PH/EH parity, horizon bounds, payout sizing, NO budget, zero return at price1, unsupported denomination and small-value reveal. Integrated build and desktop/mobile review passed. Independent review fixes were rechecked. Deferred side changes and unmounts cannot navigate; stale snapshots and removed selections block continuation. A 216-case differential matched unchanged app production/payout/cost helpers. Working-state interactions use labelled browser fixtures; separate live requests observed regional denial.

## App workspace revision — 22 October 2026

The previous long worksheet/marketing composition is user-rejected. The new user-requested benchmark is the actual app's `MinersView` and committed Rev 8 fixture: compact dark panels, a two-objective segmented control, PH/EH unit segments, short epoch presets, grouped observation/strike selections and a persistent summary. The source was inspected directly; the logged-out app screenshot is partly covered by its terms modal, so it is not evidence of every app interaction.

The public task is now three explicit stages: **Estimate → Choose market → Review**. Only the active editor is displayed; back/edit preserves values, and completed steps can be revisited. Desktop keeps the indicative summary beside it. Mobile uses a single-column editor and a sticky production/next-action strip contained inside the workspace, so it cannot cover the footer. Its pending desktop summary is hidden. Final review keeps a single app-review action in flow, reachable from the compact strip; duplicate metrics are hidden on mobile. A short title replaces the oversized hero. Model assumptions move to a named disclosure while indicative pricing, full-entry loss and app verification remain visible where needed.

Selection remains explicit: choose an observation block, then its threshold. No contract is auto-selected or substituted after refresh. Immutable market identity, rational calculations, manual fee fallback, stale/error/removed handling, cbBTC restriction and the existing preflight/handshake components are unchanged. Failed initial fetch now says data unavailable rather than continuing to say connecting. Empty cbBTC availability and removed observation-block thresholds each have explicit recovery copy. Switching objective returns to Estimate with inputs and selection preserved, so the NO risk budget is visible before review. The production comparison is expressly a constant-difficulty model, not invented network history.

Integrated production build and TypeScript passed for this revision. Browser flows passed at 320, 390, 640, 768, 1024 and 1440px with explicit test fixtures. Independent rendered review rechecked mobile stage position, readable time context and unobstructed final actions. Invalid fields, preserved edits, missing fees, removed contracts and cancellation on Back were exercised. Live data and app deployment boundaries remain unchanged.

Rendered-review corrections: mobile stage transitions place the active heading below the site header rather than returning to the objective toolbar. Observation blocks show approximate days and remaining blocks, explicitly assuming ten minutes per block; this is a pace assumption, not a forecast. At 320px horizon choices use two columns.

## Color and token refinement — 22 October 2026
