# V3.22 production-readiness audit and launch checklist

Audited on **19 October 2026**. This is a point-in-time release record, not a claim that every launch gate has passed. Owners below are **proposed responsibilities**, not confirmed assignments.

## Release decision and scope

The approved V3.22 implementation is ready to submit for the shared Vercel preview, subject to a successful deployment and smoke test of the published commit. It is **not yet ready for the `doefin.com` domain cutover**.

The maintainer explicitly authorized a pull request against `main` and its merge to trigger the existing Vercel integration. This release preserves the approved landing design, colors, section order, subscription design and public Docs. Subscription remains a prototype: no email is transmitted or stored, and the interface does not promise a real subscription.

At the start of this audit, local HEAD and remote `main` were both `d8c95a456a17656f5af93990db98ee4a680b3b9d`. The approved V3 implementation was local and uncommitted. The public `/v3` returned HTTP 404; `/` redirected to `/v1`. The current release adds `/v3` and its supporting routes. **The root redirect remains `/v1`, and V3 remains `noindex`.** No custom-domain, DNS or Vercel project settings are changed by this work.

## Preview publication gates

These are execution steps for the release PR. The deployment result belongs to the exact merged SHA, not merely a green local build.

- [ ] Commit the approved V3 implementation and this checklist on the feature branch; exclude unrelated generated agent instructions and local audit outputs.
- [ ] Open the PR against `main`; include passing checks, known check-command failures and dependency findings below.
- [ ] Inspect the PR diff and available GitHub/Vercel status for its current head.
- [ ] Merge the authorized PR with a head-SHA guard.
- [ ] Verify remote `main`, the merge commit and the Vercel Production deployment status for that commit.
- [ ] Verify `https://doefin-web.vercel.app/v3` returns V3.22, the product image loads, `/v3/docs` and a settlement guide work, and invalid routes return 404.
- [ ] Smoke-test the published subscription prototype without personal data: valid input produces the prototype completion state and no subscription network request.
- [ ] Confirm `/` still redirects to `/v1`, and V3 still carries `noindex`.
- [ ] Record the PR, merge SHA, deployment URL and browser result in the release handoff.

**Execution owner:** Fardin / engineering. **Hosting escalation:** the Vercel project owner; the maintainer does not have access to that Vercel account. No additional Vercel login is required to open or merge this repository PR.

### Dependency findings at audit time

`npm audit --omit=dev` reported **3 affected packages**, rolled up as **1 critical and 2 high**, comprising **9 underlying advisories**. These dependencies already existed on the baseline; this release does not change the package manifest or lockfile.

| Package | Observed version | Evidence and reachability boundary | Follow-up |
| --- | --- | --- | --- |
| `next` | 16.3.3 | Includes the [ImageResponse advisory](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j). Its attacker-controlled SVG prerequisite was not found in the inspected static/local-content image handlers. Other package advisories remain in the audit output. The [image-optimization SSRF advisory](https://github.com/advisories/GHSA-cjq9-62q9-8jv4) explicitly excludes configurations without `images.remotePatterns`; this project has none. No exploit test was run. | ImageResponse fix starts at 16.3.6; additional reported Next advisories require at least 16.3.8. Select and verify an appropriate patched release. |
| `sharp` | 0.35.4 | [Advisory](https://github.com/advisories/GHSA-wq5f-xc86-pv6w) depends on SVG decoding and runtime conditions. No application upload handler or direct `sharp` intake was found; the deployed binary and reachability were not verified. | Patched version starts at 0.35.5. |
| `source-map-js` | 1.2.1 | [Advisory](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) requires crafted indexed source maps to be processed. No application endpoint accepting user source maps was found. | Patched version starts at 1.2.2. |

### Existing release-check gaps

- `npm run lint` fails because it invokes `next lint`, which the installed Next version no longer provides.
- `npm run check:tools` fails on the observed local Node **20.10.0** because that runtime rejects `--experimental-strip-types`. Next's minimum runtime is satisfied, but this check's runtime requirement is not.
- No repository GitHub Actions workflows, required branch checks, rulesets or Node version pin were found at audit time. Main is unprotected. Vercel's build status is currently the available remote release signal.
- `npm run build` runs `next build`; it does not independently run the route, metadata, crawl or scenario checks described above.

## Intentionally deferred

Subscription stays a **prototype** for this release. A real email service, consent/privacy behavior, abuse controls, deliverability and unsubscribe lifecycle require a separate approved integration. Its absence is not a blocker to reviewing the approved prototype; the current UI must continue to disclose its behavior honestly.

No new interactive trading or financial execution feature is introduced by this release. App links leave the marketing preview. Root migration, domain changes, public indexing and legal publication are not bundled into the prototype merge.

## Recovery and verification limits

If the new deployment fails, inspect the GitHub Vercel status and obtain build details from the Vercel project owner. Fix the concrete failure in a scoped follow-up PR. If a published regression needs rollback, use a reviewed Git revert PR against the release merge or ask the project owner to restore a known-good deployment. The baseline is `d8c95a456a17656f5af93990db98ee4a680b3b9d`; retain the actual merge and deployment identifiers in the release handoff.

The audit did not inspect private Vercel settings, change DNS, certify financial/legal claims, run exploit tests, perform a full accessibility audit or collect field performance data. Source, local build, local browser and remote deployment evidence are separate and should remain separately reported.
